# X-Agent 标准升级文档

> 版本：v1.0
> 适用范围：X-Agent 原创内核计划仓库
> 目标：将 X-Agent 从“功能集合”升级为“可治理、可恢复、可扩展、可持续优化”的 agent 平台。

## 1. 升级目标

X-Agent 现阶段已经具备统一控制台、多中心模块、审计、记忆、工具、组织、市场、导航等基础能力。下一阶段升级目标不是继续堆叠页面，而是补齐 agent 平台的“内核能力”，让系统具备以下特征：

- **统一执行内核**：所有动作都通过标准化执行链路完成
- **统一工具协议**：工具、插件、市场能力以同一 schema 表达
- **统一上下文管理**：会话、记忆、摘要、恢复机制协同工作
- **统一治理能力**：权限、审批、审计、回放、风控形成闭环
- **统一提示工程体系**：提示词可版本化、可评估、可回归、可优化

---

## 2. 对标结论

参考 Claude Code 的成熟点，X-Agent 最值得补齐的不是单点 UI，而是下面几层：

1. **执行编排层**：任务执行、工具调用、失败恢复、重试、人工介入
2. **上下文层**：会话恢复、记忆提炼、历史检索、摘要压缩
3. **扩展层**：插件/MCP/能力市场统一协议
4. **治理层**：权限、审批、审计、风险提示
5. **提示工程层**：系统提示、任务提示、工具提示、评估提示统一管理

---

## 3. 当前架构定位

### 3.1 后端定位

当前后端以 FastAPI 为中心，已经具备：

- 多 router 聚合
- API Key 保护
- 请求日志
- 简单 rate limit
- 前端静态资源服务
- 控制中心入口 `/api/v1/entry`

### 3.2 前端定位

前端已经形成统一控制台，具备：

- 平台驾驶舱
- 运行控制
- 工具中心
- 记忆中心
- 组织权限中心
- 能力市场
- 全局导航
- 统一审计

### 3.3 现有优势

- 中心化程度高
- 入口清晰
- 适合团队和平台型产品
- 具备审计和治理雏形

### 3.4 当前短板

- 执行内核还不够统一
- 工具协议还未完全标准化
- 提示工程缺少专门治理层
- 会话恢复与上下文压缩还可进一步增强
- 市场、工具、导航之间还缺少统一语义层

---

## 4. 标准升级原则

### 4.1 先统一数据结构，再扩展能力

所有模块应优先统一：

- `resource_type`
- `resource_id`
- `primary`
- `linked_summaries`
- `risk_level`
- `status`
- `history`

### 4.2 先统一执行协议，再扩展 UI

任何功能都应先定义：

- 输入
- 输出
- 状态变迁
- 错误码
- 审计字段
- 恢复策略

### 4.3 先统一提示工程，再放大模型能力

提示词不是散落在页面或代码里的字符串，而是平台级资产。

---

## 5. 模块升级路线

## 5.1 执行控制中心升级

目标：把执行控制从“页面展示”升级为“任务内核”。

需要补齐：

- 任务状态机
- 执行追踪 trace
- 失败恢复 replay
- 人工批准 approval gate
- 超时重试 retry policy
- 执行结果归档

建议输出统一对象：

- `task_id`
- `run_id`
- `step_id`
- `action_key`
- `inputs`
- `outputs`
- `status`
- `error`
- `timestamps`
- `operator_notes`

## 5.2 工具中心升级

目标：让工具成为标准化可治理对象。

建议能力：

- 工具注册
- 工具启停
- 工具权限
- 工具版本
- 工具兼容性
- 工具调用日志
- 工具评分与风险标注

## 5.3 记忆中心升级

目标：从“记忆展示”升级为“上下文基础设施”。

建议能力：

- 会话摘要
- 记忆提炼
- 主题聚合
- 时间线回放
- 最近上下文恢复
- 相关记忆召回

## 5.4 组织权限中心升级

目标：让组织、角色、权限、审批构成治理链。

建议能力：

- 组织层级
- 角色模板
- 权限范围
- 审批流
- 风险审计
- 成员责任映射

## 5.5 能力市场升级

目标：统一外部能力接入方式。

建议能力：

- 能力发现
- 安装/启用/停用
- 版本管理
- 依赖约束
- 风险过滤
- 兼容性校验

## 5.6 全局导航升级

目标：把导航从页面入口升级为“任务导航索引”。

建议能力：

- 最近页面
- 收藏页面
- 搜索建议
- 快捷跳转
- 风险提示
- 任务关联跳转

## 6. 提示工程升级方案

这是本次升级文档的重点。

### 6.1 总原则

提示工程要从“写 prompt”升级为“管理 prompt 资产”。

每一类提示词都应该具备：

- 名称
- 版本
- 适用场景
- 输入变量
- 输出要求
- 质量标准
- 风险说明
- 回滚策略

### 6.2 提示词分层

建议分为四层：

#### A. 系统提示

定义整个 X-Agent 的行为边界：

- 角色定位
- 目标优先级
- 安全边界
- 交互原则
- 工具调用原则

#### B. 任务提示

针对具体任务场景：

- 执行控制
- 审计分析
- 工具管理
- 组织管理
- 记忆召回
- 导航推荐

#### C. 工具提示

针对工具调用规范：

- 输入格式
- 校验规则
- 容错约束
- 返回结构
- 失败处理

#### D. 评估提示

用于评估模型或工作流输出：

- 是否完整
- 是否准确
- 是否可执行
- 是否安全
- 是否符合平台策略

### 6.3 提示词治理机制

建议建立统一提示词仓库，至少包含：

- `prompt_id`
- `prompt_name`
- `version`
- `scope`
- `template`
- `variables`
- `expected_output`
- `evaluation_rules`
- `fallback_prompt`
- `owner`
- `updated_at`

### 6.4 提示工程最佳实践

- 所有 prompt 必须版本化
- 所有 prompt 必须能回滚
- 所有 prompt 必须可评估
- 所有 prompt 必须有适用边界
- 所有 prompt 必须避免隐式假设
- 所有 prompt 必须尽量结构化输出

### 6.5 提示工程建议模板

建议统一采用下面结构：

- **角色**：你是谁
- **目标**：你要完成什么
- **约束**：不能做什么
- **输入**：你会收到什么
- **输出**：你必须返回什么
- **标准**：什么算成功
- **失败处理**：遇到异常如何处理

## 7. 标准数据契约

建议为平台所有中心建立统一数据契约：

### 7.1 通用对象

```json
{
  "resource_type": "string",
  "resource_id": "string",
  "primary": {},
  "linked_summaries": {},
  "risk_level": "low|medium|high",
  "status": "active|inactive|pending|failed",
  "history": []
}
```

### 7.2 统一响应要求

- 列表接口必须支持分页或可扩展分页
- 详情接口必须返回可读摘要
- 风险字段必须显式返回
- 链接摘要必须可跳转
- 历史数据必须可回放

---

## 8. 质量门禁

每次升级都应通过以下门禁：

### 8.1 功能门禁

- 是否保留原有能力
- 是否增加了清晰的执行边界
- 是否能回滚
- 是否可恢复

### 8.2 交互门禁

- 页面是否清晰
- 术语是否统一
- 入口是否明确
- 状态是否可见

### 8.3 提示工程门禁

- prompt 是否有版本
- prompt 是否有变量声明
- prompt 是否有输出约束
- prompt 是否可测试
- prompt 是否可回退

### 8.4 平台门禁

- 是否影响现有 API 兼容性
- 是否影响审计链路
- 是否影响权限链路
- 是否影响性能

---

## 9. 推荐实施顺序

### 阶段 1：统一定义

- 定义统一对象 schema
- 定义统一执行状态机
- 定义统一 prompt 资产格式
- 定义统一审计字段

### 阶段 2：补齐内核

- execution control 内核化
- tools center 协议化
- memory center 上下文化
- marketplace 中台化

### 阶段 3：增强治理

- prompt registry
- approval flow
- policy gate
- replay and rollback

### 阶段 4：平台化优化

- 标准化导航
- 搜索与回放增强
- 多中心联动推荐
- 跨模块数据打通

## 11. 结论

X-Agent 的正确升级方向，不是再做一个“更大的控制台”，而是把它升级成：

- 可执行
- 可恢复
- 可审计
- 可治理
- 可扩展
- 可持续优化
- 可版本化提示工程

这样它才会从“应用集合”变成“真正的 agent 平台内核”。

---

## 12. 下一步建议

如果继续推进，建议立刻做三件事：

1. 建立提示工程注册表
2. 建立执行内核标准对象
3. 建立工具与记忆的统一协议层
