## 一、Agent 的总体定位

当前 X-Agent 的 Agent 核心不是单纯执行器，也不是单纯调度器，而是一个**编排优先、执行落地、具备学习与进化能力的组织型 Agent 内核**。

它需要同时承担以下职责：

1. 接收任务并理解目标
2. 先进行任务编排，再进入执行
3. 将大任务拆解到可执行步骤，并继续细化
4. 按领域、负载、能力画像进行子代理委派
5. 调用工具完成外部动作
6. 在运行前检索记忆，在运行后写回经验
7. 对执行结果进行反思、学习与能力升级
8. 在能力不足时主动到开源世界寻找可复用资源
9. 通过审计、追踪、回滚和审批机制确保可控

## 三、Agent 核心能力总览

### 1. 编排优先
- 先编排，再执行
- 先分析任务，再进入工具调用
- 先拆解目标，再分派子任务

### 2. 任务拆解
- 大任务拆解为阶段性子任务
- 子任务继续细化为可执行步骤
- 支持动态细化
- 支持多路径 / 分支拆解

### 3. 子代理委派
- 按领域匹配
- 按负载调整
- 按能力画像匹配
- 允许 Agent 自主决定谁来做
- 允许人工覆盖委派结果

### 4. 工具调用
- 支持浏览器、桌面、RPA、记忆、工作流、外部集成、文件系统、分析、管理、自定义插件工具
- 调用前做风险判断
- 高风险动作需要审批
- 支持重试与 fallback

### 5. 记忆联动
- 运行前检索上下文
- 运行后写回经验
- 保留会话连续性
- 支持长期沉淀与记忆治理

### 6. 自我进化
- 运行后反思
- 学习记录沉淀
- 能力版本提升
- 委派、工具、提示词、记忆策略优化
- 低风险可自动进化，高风险必须人工确认

### 7. 创造力 / 开源检索
- 检测到能力缺口时主动检索开源资源
- 搜索源码、框架、技能、工具、适配器
- 对候选方案进行筛选、组合、评估
- 结果写入记忆并纳入进化闭环

## 四、Agent 执行链路

### 1. 总体流程

```text
用户任务
  → API 层
  → Agent 核心
  → 任务分析
  → 记忆检索
  → 任务拆解
  → 子代理委派
  → 工具调用 / LLM 调用
  → 结果总结
  → 记忆写回
  → 反思 / 学习 / 进化
  → 返回结果
```

### 2. 编排阶段
编排阶段关注的是：

- 任务目标是什么
- 当前缺什么能力
- 需要拆成哪些步骤
- 哪些步骤适合委派给子代理
- 是否需要先去开源世界找材料

### 3. 执行阶段
执行阶段关注的是：

- 调哪些工具
- 走哪些审批
- 结果如何总结
- 是否继续推理
- 是否重试 / fallback

### 4. 收尾阶段
收尾阶段关注的是：

- 是否写回记忆
- 是否生成反思与学习记录
- 是否触发能力升级
- 是否输出开源检索与选型结果

## 五、任务拆解与委派需求

### 1. 任务拆解粒度
你确认的需求是：

- 先拆大任务，再逐步细化
- 拆到可执行步骤
- 拆到子代理级任务
- 执行中动态细化
- 支持分支拆解 / 多路径

### 2. 委派规则
你确认的规则是：

- 先按领域匹配
- 再按负载调整
- 按能力画像匹配
- 允许 Agent 自主决定谁来做
- 允许人工覆盖委派结果

### 3. 委派结构
你希望同时保留：

- 固定分工型角色
- 动态组队 / 动态分派
- 层级式委派 / 主子代理
- 并行分派多个子任务
- 失败时自动切换备选子代理

### 4. 委派边界
委派必须满足：

- 作用域限制
- 关键委派审批
- 可追踪
- 可审计
- 可重新分配

## 六、工具调用与审批控制

### 1. 工具类别
全部保留：

- 浏览器工具
- 桌面工具
- RPA / 计算机操控工具
- 记忆读写 / 巩固工具
- 工作流触发 / 控制工具
- 外部集成 / API 工具
- 文件 / 本地系统工具
- 分析 / 计算 / 检查工具
- 管理 / 运维工具
- 自定义插件工具

### 2. 风险分级
- 低 / 中 / 高三级分级
- 保留 Critical 最高风险级
- Agent 自动评估风险
- 策略可强制覆盖
- 每个工具单独配置风险策略

### 3. 审批触发
以下情况要审批：
- 高风险工具
- 影响外部系统的动作
- 写入 / 修改数据
- 删除 / 覆盖 / 破坏性操作
- 跨作用域 / 跨租户操作
- 人工显式要求审批

### 4. 工具执行流程
- 先规划再调用
- 调用前风险检查
- 调用前审批检查
- 执行后总结结果
- 写回记忆
- 继续推理 / 下一步执行
- 失败后可重试
- 失败后切换备选工具

### 5. 工具治理
- 每次调用可追踪
- 每次调用可审计
- 权限 / 作用域约束
- 允许人工接管 / 覆盖
- 可撤销 / 可回滚

## 七、记忆联动与上下文注入

### 1. 运行前注入的记忆
- 最近会话
- 最近任务运行记录
- 与当前任务强相关的记忆
- 与当前 Agent 角色相关的记忆
- 共享 / 协作记忆
- 长期记忆

### 2. 注入方式
- 直接注入上下文
- 先总结再注入
- 按相关度排序后挑选
- 分阶段逐步注入
- 受 token 预算控制

### 3. 写回内容
- 任务摘要
- 执行轨迹 / trace 关联
- 工具结果摘要
- 委派摘要
- 反思 / 学习内容
- 能力提升记录
- 绑定会话 / task / agent / tenant

### 4. 会话连续性
- 上下文可跨轮次延续
- 支持恢复会话
- 保留状态快照
- 关键记忆置顶 / 固定
- 保留最近历史窗口

### 5. 记忆治理
- 记忆版本 / 修订
- 记忆回滚
- 污染 / 冲突检查
- 允许人工纠正
- 共享范围 / 作用域控制

- 成功后
- 失败 / 异常后

### 2. 参考来源
- 反思结果
- 学习记录

## 九、创造力 / 开源检索能力

### 1. 核心目标
Agent 需要具备主动创造力，能根据任务缺口去开源世界寻找资源，再把外部能力带回来进行组合和复用。

### 2. 检索对象
- 开源仓库
- 源码片段
- 框架
- 技能 / 插件
- 工具 / 连接器
- 适配器
- 方案模式

### 3. 检索触发时机
- 检测到能力缺口时
- 任务复杂且内部能力不足时
- 用户明确要求时
- 内部工具 / 能力失败时
- 任务编排阶段预检时

### 4. 检索来源
- GitHub
- GitLab
- Codeberg / 其他开源平台
- 包管理仓库（npm / pypi / crates 等）
- 官方文档 / 示例仓库
- 社区项目 / 模板仓库

### 5. 评估维度
- 许可证 / 合规
- 安全性
- 兼容性
- 维护活跃度
- 代码质量
- 任务适配度
- 性能
- 可扩展性

### 6. 检索结果分类
- 可直接使用
- 需要改造后使用
- 仅参考
- 候选池
- 因风险 / 许可 / 兼容性被阻止

### 7. 接入路径
- 直接包装成工具
- 转换成技能
- 做成适配器层
- 嵌入工作流节点
- 人工确认后导入
- 先做原型验证再导入

### 8. 写回与沉淀
- 检索查询
- 候选列表
- 对比报告
- 采纳决策
- 接入说明
- 后续行动建议

### 9. 创造力闭环
- 任务缺口 -> 自动检索
- 检索 -> 选型
- 选型 -> 组合
- 组合 -> 记忆沉淀
- 记忆 -> 自我进化
- 人工复核 -> 回写决策

### 10. 开源治理与安全边界
- 许可证冲突 / 不兼容直接阻断
- 存在明显安全风险直接阻断
- 长期不维护 / 极低活跃直接阻断
- 代码质量太差直接阻断
- 和任务目标不匹配直接阻断
- 超出当前作用域 / 越权直接阻断
- 人工明确要求阻断直接阻断

### 11. 仅参考不引入的场景
- 只有思路可借鉴
- 只能部分复用
- 必须重写后才能用
- 风险未评估完成
- 审批未通过

### 12. 引入前检查
- 许可证扫描
- 安全扫描
- 兼容性扫描
- 依赖扫描
- 活跃度 / 维护性扫描
- 代码质量扫描

### 13. 引入后生命周期
- 先作为原型阶段
- 人工确认后正式晋级
- 随时可回滚
- 只在当前任务范围生效
- 完整写入记忆
- 全流程审计

### 14. 输出形式
- 摘要卡片
- 对比表
- 风险报告
- 接入计划
- 决策日志
- 候选排序
