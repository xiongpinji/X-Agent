## 2. 演示场景 1：多租户和团队管理

### 场景描述

### 演示步骤

**步骤 1：创建租户**

```bash
# 创建 Acme Corp 租户
POST /api/v1/enterprise/tenants
{
  "name": "Acme Corporation",
  "plan": "enterprise",
  "organization_name": "Acme Corp",
  "industry": "Technology",
  "country": "United States"
}

# 响应
{
  "id": "tenant-acme-001",
  "name": "Acme Corporation",
  "plan": "enterprise",
  "created_at": "2026-05-27T10:00:00Z"
}
```

**演示要点**：
- 展示租户隔离
- 展示租户配置选项
- 强调数据安全性

**步骤 2：创建团队**

```bash
# 在 Acme Corp 租户中创建 DevOps 团队
POST /api/v1/enterprise/tenants/tenant-acme-001/teams
{
  "name": "DevOps Team",
  "description": "Infrastructure and automation team",
  "owner_id": "user-john-001"
}

# 创建 Data Science 团队
POST /api/v1/enterprise/tenants/tenant-acme-001/teams
{
  "name": "Data Science Team",
  "description": "Analytics and ML team",
  "owner_id": "user-jane-001"
}
```

**演示要点**：
- 展示灵活的团队结构
- 展示团队所有者管理
- 强调团队隔离

**步骤 3：添加团队成员**

```bash
# 将用户添加到 DevOps 团队
POST /api/v1/enterprise/tenants/tenant-acme-001/teams/team-devops-001/members/user-alice-001

# 将用户添加到 Data Science 团队
POST /api/v1/enterprise/tenants/tenant-acme-001/teams/team-data-001/members/user-bob-001
```

**演示要点**：

## 3. 演示场景 2：SSO 集成

### 场景描述

展示如何配置 Okta SSO，实现企业级单点登录。

### 演示步骤

**步骤 1：配置 SSO**

```bash
# 配置 Okta SSO
PUT /api/v1/enterprise/tenants/tenant-acme-001/sso-config
{
  "enabled": true,
  "provider": "okta",
  "config": {
    "domain": "https://acme.okta.com",
    "client_id": "0oa1234567890abcdef",
    "client_secret": "your-client-secret",
    "authorization_server": "default",
    "scopes": ["openid", "profile", "email"]
  }
}
```

**演示要点**：
- 展示 SSO 配置界面
- 强调安全性（密钥加密存储）
- 展示支持的提供商列表

**步骤 2：用户登录流程**

```
1. 用户访问 X-Agent
2. 系统检测到 SSO 已启用
3. 重定向到 Okta 登录页面
4. 用户使用企业凭证登录
5. Okta 返回授权码
6. X-Agent 交换访问令牌
7. 自动创建/更新用户信息
8. 用户登录成功
```

**演示要点**：
- 展示无缝登录体验
- 强调自动用户配置 (JIT)
- 展示用户信息同步

**步骤 3：用户自动配置**

```bash
# 获取 SSO 用户信息
GET /api/v1/enterprise/tenants/tenant-acme-001/users/user-sso-001

# 响应
{
  "id": "user-sso-001",
  "email": "alice@acme.com",
  "display_name": "Alice Johnson",
  "sso_provider": "okta",
  "sso_id": "00u1234567890abcdef",
  "department": "Engineering",
  "is_verified": true
}
```

**演示要点**：
- 展示自动创建的用户
- 展示从 SSO 同步的属性
- 强调减少管理工作

## 5. 演示场景 4：实际应用 - 自动化采购流程

### 场景描述

展示如何使用 X-Agent 企业版自动化采购审批流程。

```

3. 发送给部门经理审批
4. 发送给财务审批

6. 发送给供应商
```

```bash
POST /api/v1/workflows

      "id": "step-1",

    },
    {
      "id": "step-2",
      "name": "Manager Approval",
      "type": "approval",
      "approver_role": "team_lead"
    },
    {
      "id": "step-3",
      "name": "Finance Approval",
      "type": "approval",
      "approver_role": "tenant_admin"
    },
    {
      "id": "step-4",
      "name": "Generate PO",
      "type": "agent",
      "agent_id": "agent-po-generator"
    },
    {
      "id": "step-5",
      "name": "Send to Vendor",
      "type": "agent",
      "agent_id": "agent-vendor-notifier"
    }
  ]
}
```

**演示要点**：
- 展示工作流编辑器

## 8. 常见问题和回答

### Q1: 数据安全性如何保证？

**回答**：
- 所有数据在传输中使用 TLS 1.3 加密
- 敏感数据在存储时使用 AES-256 加密
- 完整的审计日志记录所有访问
- 定期安全审计和渗透测试
- SOC 2 Type II 认证

### Q2: 如何处理数据隐私和 GDPR 合规？

**回答**：
- 支持数据导出和删除
- 自动生成 GDPR 合规报告
- 数据驻留选项（EU、US、APAC）
- 隐私政策和数据处理协议
- 定期隐私审计

### Q3: 支持哪些 SSO 提供商？

**回答**：
- Okta
- Azure AD
- Google Workspace
- 自定义 SAML 2.0
- 支持自定义集成

### Q4: 如何处理高可用性和灾难恢复？

**回答**：
- 99.9% SLA（Enterprise 版）
- 多区域部署
- 自动故障转移
- 定期备份和恢复测试
- 灾难恢复计划

### Q5: 支持哪些集成？

**回答**：
- Slack、Teams、Discord
- Jira、GitHub、GitLab
- Salesforce、HubSpot
- Zapier、IFTTT
- 自定义 API 集成
