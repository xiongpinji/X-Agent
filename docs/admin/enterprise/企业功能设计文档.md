## 1. 企业功能概览

### 1.1 核心功能模块

#### 多租户支持 (Multi-Tenancy)
- 完全隔离的租户数据
- 租户级别的配置管理
- 租户级别的资源限制
- 租户级别的计费和使用统计

#### SSO 单点登录 (Single Sign-On)
- 支持 Okta、Azure AD、Google Workspace
- SAML 2.0 和 OAuth 2.0 协议
- 自动用户配置 (Just-In-Time Provisioning)
- 自动用户同步

#### 团队协作 (Team Collaboration)
- 灵活的团队结构
- 团队成员管理
- 团队级别的权限控制
- 团队工作空间隔离

#### 权限管理系统 (RBAC)
- 预定义角色：Super Admin、Tenant Admin、Team Lead、Developer、Viewer、Guest
- 细粒度权限控制
- 动态权限分配
- 权限继承和组合

#### 审计日志 (Audit Logging)
- 完整的操作审计
- 变更追踪
- 合规性报告
- 安全事件记录

#### API 密钥管理
- 安全的 API 密钥生成和存储
- 密钥轮换策略
- 速率限制
- 密钥过期管理

## 2. 架构设计

### 2.1 多租户架构

```
┌─────────────────────────────────────────────────────┐
│                  API Gateway                        │
│         (租户识别、请求路由、速率限制)              │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│              Enterprise Service Layer               │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  │ Tenant Mgmt  │  │  User Mgmt   │  │  Team Mgmt   │
│  └──────────────┘  └──────────────┘  └──────────────┘
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  │ RBAC Engine  │  │ Audit Logger │  │ SSO Handler  │
│  └──────────────┘  └──────────────┘  └──────────────┘
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│              Data Isolation Layer                   │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  │ Tenant Data  │  │ Tenant Data  │  │ Tenant Data  │
│  │  (Tenant 1)  │  │  (Tenant 2)  │  │  (Tenant N)  │
│  └──────────────┘  └──────────────┘  └──────────────┘
└─────────────────────────────────────────────────────┘
```

### 2.2 数据隔离策略

**行级隔离 (Row-Level Isolation)**
- 每条记录包含 `tenant_id` 字段
- 数据库查询自动过滤租户数据
- 应用层强制租户边界检查

**模式隔离 (Schema Isolation)**
- 可选：为每个租户创建独立的数据库模式
- 适用于高度隔离的企业客户

**数据库隔离 (Database Isolation)**
- 可选：为每个租户创建独立的数据库
- 适用于最高级别的隔离需求

### 3.3 权限检查流程

```python
def check_permission(user: EnterpriseUser, permission: PermissionType) -> bool:
    # 1. 检查用户是否为 Super Admin
    if user.role == RoleType.SUPER_ADMIN:
        return True
    
    # 2. 检查用户是否被禁用
    if not user.is_active:
        return False
    
    # 3. 检查显式权限
    if permission in user.permissions:
        return True
    
    # 4. 检查角色默认权限
    role_permissions = get_role_permissions(user.role)
    return permission in role_permissions
```

## 4. SSO 集成

### 4.1 支持的 SSO 提供商

- **Okta**：企业级身份管理
- **Azure AD**：Microsoft 企业生态
- **Google Workspace**：Google 企业应用
- **自定义 SAML 2.0**：任何支持 SAML 的提供商

### 4.2 SSO 配置示例

#### Okta 配置

```json
{
  "provider": "okta",
  "config": {
    "domain": "https://your-domain.okta.com",
    "client_id": "0oa1234567890abcdef",
    "client_secret": "your-client-secret",
    "authorization_server": "default",
    "scopes": ["openid", "profile", "email"]
  }
}
```

#### Azure AD 配置

```json
{
  "provider": "azure_ad",
  "config": {
    "tenant_id": "your-tenant-id",
    "client_id": "your-client-id",
    "client_secret": "your-client-secret",
    "authority": "https://login.microsoftonline.com/your-tenant-id"
  }
}
```

### 4.3 SSO 流程

```
用户访问 X-Agent
    ↓
检查是否已认证
    ↓ (未认证)
重定向到 SSO 提供商
    ↓
用户在 SSO 提供商登录
    ↓
SSO 提供商返回授权码
    ↓
X-Agent 交换访问令牌
    ↓
获取用户信息
    ↓
自动配置用户 (JIT)
    ↓
创建会话
    ↓
重定向到应用
```

## 5. 审计日志系统

### 5.1 审计事件类型

| 事件类型 | 描述 | 敏感度 |
|---------|------|--------|
| USER_LOGIN | 用户登录 | 中 |
| USER_LOGOUT | 用户登出 | 低 |
| USER_CREATED | 创建用户 | 高 |
| USER_DELETED | 删除用户 | 高 |
| USER_ROLE_CHANGED | 角色变更 | 高 |
| AGENT_EXECUTED | 执行 Agent | 中 |
| WORKFLOW_EXECUTED | 执行工作流 | 中 |
| WORKFLOW_APPROVED | 批准工作流 | 中 |
| API_KEY_CREATED | 创建 API 密钥 | 高 |
| API_KEY_REVOKED | 撤销 API 密钥 | 高 |
| POLICY_CHANGED | 策略变更 | 高 |
| SECURITY_EVENT | 安全事件 | 高 |

### 5.2 审计日志查询

```bash
# 查询特定时间范围的审计日志
GET /api/v1/enterprise/tenants/{tenant_id}/audit-logs?start_date=2026-05-01&end_date=2026-05-31

# 查询特定事件类型
GET /api/v1/enterprise/tenants/{tenant_id}/audit-logs?event_type=USER_CREATED

# 查询特定用户的操作
GET /api/v1/enterprise/tenants/{tenant_id}/audit-logs?actor_id={user_id}
```

## 7. API 密钥管理

### 7.1 创建 API 密钥

```bash
POST /api/v1/enterprise/tenants/{tenant_id}/api-keys
{
  "name": "CI/CD Pipeline",
  "user_id": "user-123",
  "permissions": [
    "agent:read",
    "agent:execute",
    "workflow:read",
    "workflow:execute"
  ],
  "rate_limit": 1000,
  "expires_at": "2027-05-27T00:00:00Z"
}
```

### 7.2 API 密钥安全最佳实践

- 密钥存储使用 SHA-256 哈希
- 密钥仅在创建时显示一次
- 支持密钥轮换
- 支持密钥过期
- 支持速率限制
- 支持权限范围限制

### 7.3 API 密钥使用

```bash
curl -H "Authorization: Bearer {api_key}" \
     https://x-agent.example.com/api/v1/agents
```

## 9. 部署指南

### 9.1 环境变量配置

```bash
# 企业功能开关
ENTERPRISE_ENABLED=true

# 多租户配置
MULTI_TENANCY_ENABLED=true
TENANT_ISOLATION_LEVEL=row  # row, schema, database

# SSO 配置
SSO_ENABLED=true
SSO_PROVIDERS=okta,azure_ad,google

# 审计日志
AUDIT_LOG_ENABLED=true
AUDIT_LOG_RETENTION_DAYS=365

# 数据库
DATABASE_URL=postgresql://user:password@localhost/xagent_enterprise
```

### 9.2 数据库初始化

```bash
# 创建企业表
python -m backend.scripts.init_enterprise_db

# 创建初始租户
python -m backend.scripts.create_tenant \
  --name "Acme Corp" \
  --plan enterprise \
  --organization-name "Acme Corporation"
```

### 9.3 Docker 部署

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install -r requirements.txt

COPY backend/ ./backend/

ENV ENTERPRISE_ENABLED=true
ENV MULTI_TENANCY_ENABLED=true

CMD ["uvicorn", "backend.app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

A: 使用管理员界面或 API：
