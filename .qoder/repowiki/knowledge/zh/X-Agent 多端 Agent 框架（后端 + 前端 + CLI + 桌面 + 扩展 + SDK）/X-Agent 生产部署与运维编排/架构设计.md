模块按「可配置模板 → 静态清单 → 运维脚本」三层组织：
- `helm/` 是权威的可变层，`Chart.yaml` + `values.yaml`/`values-production.yaml` 驱动 `templates/*.yaml`（api/worker/beat Deployment、Postgres/Redis/Qdrant/Neo4j StatefulSet、Ingress、Secret、ConfigMap、ServiceAccount/RBAC），并通过 `_helpers.tpl` 的 `xagent.*Host` 模板在 `enabled=true` 时解析集群内 Service 名、`false` 时强制要求 `external.*Host`，实现内置组件与外部托管实例的双模式切换。
- `k8s/` 存放未渲染的原始 YAML（含 `xagent-api`、`xagent-worker`、`xagent-beat`、各依赖组件及 `backup-cronjob`），作为不安装 Helm 时的最小可用基线；根目录 `k8s/deployment.yml` 将 Namespace/ConfigMap/Secret/Deployment/Service/HPA/PDB/NetworkPolicy 打包成单文件一键 `kubectl apply`。
- `scripts/` 提供端到端流水线：`deploy.sh` 校验 kubectl/helm/docker → 构建镜像 → `helm upgrade --install` → rollout 等待 → alembic 迁移；`rollback.sh` 支持回滚到上一版本或指定 image tag，并可选执行 `migrate.py rollback` 回退数据库 schema。
- `canary/` 通过 `canary-deployment.yaml` + `deploy-canary.sh` 实现金丝雀发布；`backup/` 用独立 Dockerfile 构建含 pg_dump/redis-cli/curl/jq 的备份镜像，由 CronJob 触发。
- `prometheus/`、`alertmanager/`、`grafana/` 构成本地可复现的监控子集，配合 `docker-compose.monitoring.yml` 和 `MONITORING_QUICKSTART.md` 快速拉起；`env/` 仅含 README 说明环境变量约定。
依赖方向单向：脚本调用 helm/kubectl，Helm 模板引用 values，静态清单与 Helm 模板保持资源命名一致以便互相替代。
