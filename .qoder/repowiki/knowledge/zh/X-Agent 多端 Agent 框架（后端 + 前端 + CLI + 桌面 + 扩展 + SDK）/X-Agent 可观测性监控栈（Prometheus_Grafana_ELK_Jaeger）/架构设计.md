本模块以 `docker-compose.monitoring.yml` 为编排入口，在同一 bridge 网络 `x-agent-network` 上启动 Prometheus、AlertManager、Grafana、Node Exporter、Elasticsearch、Logstash、Kibana、Jaeger、Postgres Exporter、Redis Exporter、Qdrant、Postgres、Redis 等容器，并通过命名卷持久化数据。

- 指标层：权威配置收敛于 `monitoring/prometheus.yml`（P0-04 后根目录与子目录多份已归档至 `archive/`），仅抓取 `localhost:8000/api/v1/metrics/prometheus`（backend 实际挂载端点）以及 node/postgres/redis/qdrant exporter；`alert_rules.yml` 与 `recording_rules.yml` 经 `rule_files` 挂接，但录制规则依赖的 `xagent_api_*` 原始指标需 backend 侧 P0-04 接线后才产出。
- 可视化层：Grafana 通过 `grafana/provisioning/datasources.yml` 自动注册 Prometheus 数据源，仪表板 JSON 文件置于 `grafana/dashboards/` 并由 compose 挂载到 `/var/lib/grafana/dashboards`。
- 日志层：`elk/logstash.conf` 定义 file/syslog/http/tcp/udp 多输入，按 type 分支解析 JSON 并写入 `xagent-*` / `xagent-critical-*` / `xagent-audit-*` 索引，由 Kibana 展示。
- 追踪层：Jaeger all-in-one 镜像暴露 OTLP/Zipkin/gRPC 端口，配合 `jaeger-config.yml` 使用。
- 告警层：AlertManager 独立容器，配置文件 `alertmanager.yml` 及 `alertmanager/config.yml` 通过 volume 注入。
- 运维脚本：`scripts/` 下提供 `autorestart.sh`、`autoscaling.sh`、`backup.sh`、`verify-deployment.sh`；顶层 `deploy-monitoring.sh`、`quickstart.sh`、`verify-monitoring.sh` 封装常用操作。
