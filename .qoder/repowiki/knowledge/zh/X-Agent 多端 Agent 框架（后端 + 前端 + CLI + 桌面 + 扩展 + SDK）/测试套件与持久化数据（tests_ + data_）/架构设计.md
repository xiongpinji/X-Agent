测试按场景分层组织在 tests/ 下：
- 根目录 `test_*.py` 为通用单元测试，通过 `conftest.py` 中的 `_init_global_db` autouse fixture 注入临时文件 SQLite（`sqlite+aiosqlite:///{tmp}/test.db`）+ `NullPool`，避免 aiosqlite 跨 event loop 死锁；同时用 fakeredis 替代真实 Redis，并通过 `_reset_global_state` 清理全局速率限制、token、租户/用户缓存。
- `agent_v2/`、`enterprise/`、`e2e/`、`integration/`、`performance/`、`runtime/`、`contracts/`、`mcp_fixtures/` 为子包级 conftest 覆盖根级 fixture，分别初始化对应数据库 Base（如 enterprise 仅建 billing.Base）并隔离数据目录。
- 性能测试位于 `tests/performance/`，由 `run_tests.py` 通过 `pytest.main` 以 `-m benchmark/load_test/stress_test/stability_test/bottleneck_analysis` 标记分组执行，配合 `config.py` 中 `PerformanceTestConfig` / `PerformanceTargets` / `PerformanceGrades` 配置类驱动基准、负载、压力、稳定性与瓶颈分析用例，并使用 Locust (`locustfile.py`) 做并发压测。
- `tests/run_comprehensive_tests.py`、`tests/run_enterprise_tests.py` 是顶层编排脚本，内部再调用 pytest 子进程执行指定用例集并汇总结果。
- `data/` 提供不可变种子数据：`agent_contexts/` 下的 `session_*` 与 `snapshot_*` JSON 用于 agent 上下文恢复与快照对比；`sessions/session-1/` 包含结构化会话目录（metadata.json + state.json + 多份 snapshot）；`migrations/` 存放迁移 JSON 及 `versions.json`；其余 `audit.jsonl`、`runs.jsonl`、`workflow_runs.jsonl`、`approvals.json`、`tool_executions.json`、`workflows.json`、`api_keys.json` 等作为 Store 层序列化契约的断言基线。`data/` 被测试直接读取，不随运行修改。
