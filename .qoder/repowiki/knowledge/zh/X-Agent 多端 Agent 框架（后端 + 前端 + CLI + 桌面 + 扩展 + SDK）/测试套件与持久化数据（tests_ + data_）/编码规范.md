- 每个子测试包（agent_v2、enterprise、e2e、performance 等）都自带 `conftest.py`，通过同名 `_init_global_db` autouse fixture 覆盖根级数据库初始化，确保不同场景使用独立的临时 SQLite 与对应的 SQLAlchemy Base。
- 异步数据库 fixture 一律采用 `sqlite+aiosqlite` + `NullPool` + `check_same_thread=False` + `timeout=30` 的组合，并在 teardown 中 `engine.dispose()` + 删除临时目录，避免 aiosqlite 后台线程跨 event loop 挂起。
- 需要访问 `SessionManager.get_session()` 的测试通过注入 `backend.app.core.database._db_manager` 的全局替换来复用生产代码路径，而非自建连接。
- 性能测试通过自定义 pytest marker（benchmark / load_test / stress_test / stability_test / bottleneck_analysis）在 `performance/config.py` 的 `PerformanceTestConfig` 中集中声明阈值与目标，再由 `run_tests.py` 统一调度。
- 持久化种子数据以 UUID 命名的 JSON/JSONL 文件存放在 `data/` 下，文件名即主键 ID，便于断言精确匹配且支持增量追加（如 migrations 的 `versions.json`）。
