## 架构设计

### 1. 多区域部署

```
全局负载均衡器 (Route53)
    ↓
┌─────────────────────────────────────┐
│  主区域 (US-E) - 活跃                │
│  ├─ 应用层 (3x)                     │
│  ├─ PostgreSQL (主)                 │
│  ├─ Redis (主)                      │
│  ├─ Qdrant (主)                     │
│  └─ Neo4j (主)                      │
└─────────────────────────────────────┘
    ↓ (实时同步)
┌─────────────────────────────────────┐
│  备用区域 (US-W) - 热备              │
│  ├─ 应用层 (3x)                     │
│  ├─ PostgreSQL (从)                 │
│  ├─ Redis (从)                      │
│  ├─ Qdrant (从)                     │
│  └─ Neo4j (从)                      │
└─────────────────────────────────────┘
```

### 2. 数据同步拓扑

**PostgreSQL**:
- 流复制 (Streaming Replication)
- WAL日志 (Write-Ahead Logging)
- 同步延迟: <1秒

**Redis**:
- 主从复制 (Master-Slave Replication)
- 异步同步
- 同步延迟: <5秒

**Qdrant**:
- 快照 + 增量同步
- 同步延迟: <10分钟

**Neo4j**:
- 事务日志 + 增量同步
- 同步延迟: <10分钟

### 3. 故障转移决策树

```
故障检测 (10秒)
    ↓
故障分类
    ├─ 应用故障 → 自动重启 (5分钟)
    ├─ 数据库故障 → 主从切换 (15分钟)
    ├─ 网络故障 → 本地重试 (5分钟)
    └─ 数据中心故障 → 跨区域转移 (45分钟)
```

## 操作流程

### 故障检测到恢复的完整流程

```
T+0秒: 故障发生
  ↓
T+10秒: 健康检查失败
  ↓
T+30秒: 触发告警
  ↓
T+45秒: 自动故障转移开始
  ↓
T+60秒: DNS更新完成
  ↓
T+90秒: 流量转移完成
  ↓
T+120秒: 恢复验证开始
  ↓
T+300秒: 恢复验证完成
  ↓
T+600秒: 运维团队接收通知
  ↓
T+1800秒: 故障根因分析开始
```

### 应用服务故障响应

```bash
# 1. 检查应用状态
docker ps | grep xagent-api

# 2. 查看应用日志
docker logs xagent-api | tail -100

# 3. 重启应用
docker restart xagent-api

# 4. 如果重启失败，执行故障转移
./scripts/failover.sh --auto

# 5. 验证恢复
./scripts/verify-recovery.sh
```

### 数据库故障响应

```bash
# 1. 检查数据库状态
psql -h localhost -U xagent -d xagent_db -c "SELECT version();"

# 2. 检查复制状态
psql -c "SELECT * FROM pg_stat_replication;"

# 3. 执行主从切换
./scripts/failover.sh --manual --region us-west --force

# 4. 验证恢复
./scripts/verify-recovery.sh
```
